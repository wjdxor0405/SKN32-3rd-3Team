# data/guide — 배출 가이드 폴더

`python -m scripts.seed_docs` 가 이 폴더의 파일을 읽어
`documents` 테이블에 `source_type="guide"` 로 적재한다.
(법령은 `data/laws/` 에 넣는다)

관리자 문서 업로드(`/api/admin`)의 저장 위치이자 `RAG_SOURCE=files` 모드의 검색 경로이기도 하다.
(과거 `data/guides` 와 이원화되어 있던 것을 `data/guide` 로 통일함 — 2026-08-03)

## 문서 작성 규칙

**첫 줄이 문서 제목**이 된다. `[` 로 시작하면 그 줄을, 아니면 파일명을 쓴다.
답변에서 "서울시 기준으로는…" 처럼 인용되므로 **지역이 드러나게** 쓸 것.

```
[서울시] 분리배출 가이드 및 재활용품목 배출 요령

출처: 서울특별시 환경분야 누리집
지역: seoul

=== 품목별 분리배출 요령 ===

[종이류]
- 신문지: ...
- 종이컵: ...

[비닐류]
- ...
```

## 청킹 방식

가이드는 **품목 블록 단위**로 잘린다.

| 표기 | 역할 |
|---|---|
| `=== 큰 구획 ===` | 상위 분류 (품목별 요령 / 음식물쓰레기 요령 …) |
| `[품목]` | 청크 경계. 이 블록 하나가 검색 단위가 된다 |

청크에는 `품목별 분리배출 요령 > 종이류` 형태의 위치 정보가 붙어,
검색 결과와 답변 출처에 함께 표시된다.

> 700자 단위로 기계적으로 자르면 "[종이류]" 설명이 중간에 끊겨
> "종이컵은 어디에?" 질문에 반쪽짜리 근거만 잡힌다. 그래서 블록 단위로 나눈다.

## 지역(region) 규칙 — 새 지역 추가 시 코드 수정 필요

파일명의 지역 키워드로 region 코드가 결정된다
(`app/services/rag_service.py` 의 `REGION_MAP`: 서울→seoul, 천안→cheonan, 부산남구→busan_namgu, 공통·환경부→common).

- 파일명은 `[가이드]_지역명_주제.txt` 형식을 지킬 것. 매핑에 없는 키워드는 전부 `common` 처리된다
- **새 지자체 가이드를 추가할 때는 `REGION_MAP` 에 항목을 함께 추가해야 한다**
  (누락 시 지역 필터가 무력화되어 타 지역 답변이 섞임). 프론트에 지역 선택 UI가 있으면 그쪽 목록도 갱신
- 전국 공통 문서(특수 배출 절차 등)는 파일명에 `공통` 을 넣어 common 으로 둔다

## 지역 자료는 2곳 이상

지자체마다 기준이 다른 것이 이 프로젝트의 핵심 논거다.
(예: 부산 남구는 비닐을 매주 월요일 배출, 서울시는 요일 지정 없음)
**반드시 2개 이상 지자체 자료를 넣을 것.**

## 지원 형식

`.txt` `.md` `.pdf` — PDF는 머리말·꼬리말·페이지번호가 자동 제거된다.
`README.md` 와 `_` 로 시작하는 파일은 시드에서 무시된다.
(`RAG_SOURCE=files` 모드도 동일한 제외 규칙을 따른다 — 2026-08-03 패치)

수집·정제 기록은 `_dataguide_수집_정제_이력.md` 에 남긴다.
